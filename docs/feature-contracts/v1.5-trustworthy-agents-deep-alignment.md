# Feature Contract — v1.5 Trustworthy-Agents deep alignment

**Branch**: `harness/v1.5-trustworthy-agents-deep-alignment`
**Base**: `harness/v1.4-speckit-bmad-alignment`
**Date**: 2026-04-20
**Status**: In review (PR open for human gate)

## Why this exists

External audit against Anthropic's [trustworthy-agents](https://www.anthropic.com/research/trustworthy-agents) and [harness-design-long-running-apps](https://www.anthropic.com/engineering/harness-design-long-running-apps) — plus 2026 evolutions of BMAD V6, GitHub SpecKit, and Superpowers — surfaced six gaps the v1.4 alignment pass did not close. Each is grounded in a documented anti-pattern or a direct prescription from the source material.

| FR | Title | Source tradition | The gap v1.5 closes |
|----|-------|------------------|---------------------|
| FR-1 | Subagent observability streaming | Trustworthy Agents §opacity at scale | Subagent dispatches are fire-and-wait black boxes; a 20-min Generator run shows the human nothing. Trustworthy Agents names this directly. v1.4 explicitly deferred this as P2; v1.5 closes it because it's a *named anti-pattern*, not polish. |
| FR-2 | Hook-enforced spec-file ownership | BELCORT-specific (defensive depth) | The "orchestrator does NOT edit spec files" rule (SKILL.md §File Ownership Contract) is enforced only by prose. A future Claude can violate it. v1.5 promotes the rule to a hook check — behavioral → enforced. |
| FR-3 | Mid-build pause-and-ask | Trustworthy Agents §calibrated uncertainty | Generator hits genuine ambiguity → guess silently or fail. Trustworthy Agents emphasizes *"Claude's choice to pause"* as a trained capability. Planner has AskUserQuestions; Generator has no equivalent — precisely where the cost of guessing is highest. |
| FR-4 | Per-FR story files | BMAD V6 Scrum Master pattern | Aggregate contract.md bundles all FRs; Generator re-reads everything per cycle. BMAD V6 ships hyper-detailed per-story files with embedded persona + arch + dev guidance. Closes the per-cycle context-quality gap. |
| FR-5 | Component-as-assumption stress test | Rajasekaran 2026 (direct quote) | *"Every component in a harness encodes an assumption about what the model can't do on its own, and those assumptions are worth stress testing."* Not operationalized anywhere. v1.5 adds a meta-process to prevent silent accumulation of dead weight. |
| FR-6 | Constitution amendment governance | SpecKit explicit constitutional governance | Constitution is "immutable post-init" — strong but rigid. Real projects need amendment paths (post-incident security rules, scope drift). SpecKit has explicit governance; v1.5 adopts the pattern with high ceremony. |

## Scope — FRs

### FR-1 — Subagent observability streaming

**Problem.** Orchestrator dispatches Generator/Evaluator with `claude -p` (sprint.md:90-275) and blocks until exit. Human sees nothing during the run. Trustworthy Agents calls this out by name.

**Approach.** Lightweight heartbeat — subagents append one structured JSONL line per milestone to `.harness/features/${FEATURE}/_progress.jsonl`. Orchestrator polls (every 10s) and prints compact lines to user.

**Artifacts.**
- New: `plugins/harness/agents/_progress-protocol.md` — shared protocol doc
- Edit: all three `agents/*.md` — add §Progress Logging
- Edit: `commands/sprint.md` — wrap each dispatch with a polling reader
- Edit: `templates/manifest.yaml` — `config.observability.heartbeat: true`

### FR-2 — Hook-enforced spec-file ownership

**Problem.** SKILL.md:86-95 declares "orchestrator does NOT edit spec files." Behavioral only. pre-tool-use.sh:69 inspects only Bash.

**Approach.** Extend pre-tool-use.sh to inspect Edit/Write tool calls. Block writes to `.harness/spec/*`, `.harness/features/*/contract.md`, `.harness/evaluator/criteria.md` when `CLAUDE_SUBAGENT≠1` AND `state.phase` isn't one of `amending|clarifying|editing|tuning|retrospecting|constitution-amending`. Each spec-editing command sets/clears its phase at boundaries.

**Artifacts.**
- Edit: `plugins/harness/hooks/pre-tool-use.sh` (+~40 lines)
- Edit: `commands/{amend,clarify,edit,tune-evaluator,retrospective}.md` — set/clear `state.phase` at boundaries
- Edit: `templates/manifest.yaml` — document the new phase enum values
- Edit: `plugins/harness/skills/harness/SKILL.md` File Ownership Contract — add "Enforcement" line

### FR-3 — Mid-build pause-and-ask

**Problem.** Generator hits ambiguity mid-build → guess silently → likely fails Evaluator. No structured pause path. Trustworthy Agents §calibrated uncertainty calls this out.

**Approach.** File-based pause matching existing comm pattern. Generator writes `.harness/features/${FEATURE}/pause-questions.md` with structured Q + mandatory "default if unanswered" fallback. Sets `implementation-report.md` status to `PAUSED`. Orchestrator detects, surfaces to user (same UX as `/harness:clarify`), re-dispatches fresh Generator with answers. Pause counter increments existing `agent_checkins` metric.

**Artifacts.**
- Edit: `agents/generator.md` — add §Pause Protocol (when, when NOT, format, default-fallback rule, RED FLAG against pause-as-procrastination)
- Edit: `commands/sprint.md` — step 3 detects pause-questions.md, branches to user-input loop, re-dispatches
- New: `plugins/harness/templates/features/pause-questions.md.txt` (runtime-readable via `${CLAUDE_PLUGIN_ROOT}/templates/...`)

### FR-4 — Per-FR story files

**Problem.** Aggregate contract.md bundles all FRs. Generator BUILD context bloats with FR count; per-cycle reasoning quality degrades; recovery requires full contract re-read.

**Approach.** Planner Pass 2 emits ONE story per FR alongside the aggregate contract: `.harness/features/NNN-name/stories/FR-NNN.md`. Each story contains: FR + ACs + ECs (verbatim, ID-referenced — never paraphrased), persona snippet, arch slice, applicable constitution principles, dev guidance from negotiation. Generator BUILD reads the *current* story per cycle; aggregate contract consulted only for cross-FR concerns. Evaluator continues to read aggregate contract (its source of truth unchanged).

**Artifacts.**
- New: `plugins/harness/templates/features/story.md.txt` (runtime-readable via `${CLAUDE_PLUGIN_ROOT}/templates/...`)
- Edit: `agents/planner.md` Pass 2 — emit `stories/` directory
- Edit: `agents/generator.md` BUILD phase — read story per cycle
- Edit: `commands/sprint.md` — Generator dispatch context includes the *current* story
- Edit: `plugins/harness/skills/harness/SKILL.md` — add stories/ rows to File Ownership Contract

### FR-5 — Component-as-assumption stress test

**Problem.** Direct quote from Rajasekaran 2026 not operationalized. Harness silently accumulates dead weight as model capability evolves.

**Approach.** New command `/harness:assumption-test "<component>"` runs a calibrated A/B: same canary spec WITH and WITHOUT the named component. Compares scores, CRITICAL counts, TDD evidence quality, tokens. Verdict: `LOAD-BEARING` / `MARGINAL` / `OBSOLETE`. Initial testable components: brainstorm, negotiation, two-stage-eval, red-flags-section, calibration-examples, reward-hacking-scan, analyze. Quarterly cadence recommended.

**Artifacts.**
- New: `plugins/harness/commands/assumption-test.md`
- New: `plugins/harness/scripts/assumption-test.sh`
- Edit: `templates/manifest.yaml` — `harness.last_assumption_test: { date, component, verdict }`
- Edit: `docs/anthropic-alignment.md` — add row mapping to Rajasekaran 2026

### FR-6 — Constitution amendment governance

**Problem.** Constitution is immutable; real projects need amendment paths. Currently the only path is to manually edit the file, violating both file-ownership and immutability rules.

**Approach.** New command `/harness:constitution-amend "<reason>"` with high ceremony:
1. Pre-flight gates: typed confirmation `I-AM-AMENDING-THE-CONSTITUTION`, reason ≥ 50 chars, in-progress feature handling
2. Dispatch Planner in CONSTITUTION-AMEND mode → produces `constitution-amend-patches.md` (file-based, reviewable)
3. Mandatory ADR in `progress/decisions.md`
4. Re-validation pass: dispatch Evaluator in REVALIDATE mode against each completed feature; per-feature user decision (backport / grandfather)
5. Apply patches only after user reviews patches AND revalidation report

**Artifacts.**
- New: `plugins/harness/commands/constitution-amend.md`
- Edit: `agents/planner.md` — add CONSTITUTION-AMEND mode
- Edit: `agents/evaluator.md` — add REVALIDATE mode
- Edit: `plugins/harness/skills/harness/SKILL.md` — add constitution-amend writer to File Ownership Contract
- Edit: `templates/manifest.yaml` — `constitution.amendments: []` history
- Edit: `pre-tool-use.sh` (FR-2 layer) — allow constitution.md write when `phase=constitution-amending`

## ACs (testable)

### AC-1.1 — Heartbeat protocol exists
`plugins/harness/agents/_progress-protocol.md` exists, ≤80 lines, defines:
- JSONL schema (`ts`, `agent`, `phase`, `fr|ac` (optional), `msg`)
- When to emit (mode start, TDD phase boundary, FR/AC tested, blockers)
- Rate limit (max 1 per 30s per agent)
- File path convention

### AC-1.2 — Each agent prompt references the protocol
`agents/{planner,generator,evaluator}.md` each have a §Progress Logging section that points to `_progress-protocol.md` and lists agent-specific milestone events.

### AC-1.3 — Sprint command polls and surfaces
`commands/sprint.md` step 3 dispatch wraps each `claude -p` invocation with a backgrounded poller that reads new lines from `_progress.jsonl` every 10s and prints them in compact `[HH:MM AGENT] event` form. Poller cleans up on dispatch exit.

### AC-1.4 — Manifest supports the toggle
`templates/manifest.yaml` includes `config.observability.heartbeat: true`. When false, agents skip emission; orchestrator skips polling.

### AC-2.1 — Hook enforces spec-file ownership
`pre-tool-use.sh` inspects Edit and Write tool calls. Blocks writes to `.harness/spec/*`, `.harness/features/*/contract.md`, `.harness/evaluator/criteria.md` when (a) `CLAUDE_SUBAGENT≠1` AND (b) `manifest.yaml` `state.phase` is not in the allowed set: `amending|clarifying|editing|tuning|retrospecting|constitution-amending`.

### AC-2.2 — Allowed paths bypass the gate
Subagent writes (CLAUDE_SUBAGENT=1) bypass entirely. `manifest.yaml`, `progress/*`, source code outside `.harness/` are not blocked.

### AC-2.3 — Phase transitions wired
`commands/{amend,clarify,edit,tune-evaluator,retrospective,constitution-amend}.md` each set the appropriate `state.phase` value at command entry and clear it at exit (success OR failure path).

### AC-2.4 — Existing safety rails intact
Force-push block, sudo block, `.harness/` deletion block, test-file deletion block during BUILD phase — all still fire as before.

### AC-3.1 — Generator pause protocol section
`agents/generator.md` has a §Pause Protocol section explicitly placed within MODE: BUILD. Defines: when to pause (genuine ambiguity, not risk-aversion), file format with mandatory "default if unanswered", exit signal (status `PAUSED` in implementation-report.md), RED FLAG against pause-as-procrastination.

### AC-3.2 — Pause questions template

### AC-3.3 — Sprint detects pause and resumes

## Testing strategy

This is a prompt-engineering + shell-script repo — no Playwright, no test runner. Verification is:

1. **Lint pass** — `bash -n` on all modified shell scripts (pre-tool-use.sh, doctor.sh, assumption-test.sh)
2. **Hook simulation** — pipe synthetic JSON to pre-tool-use.sh in each phase scenario; verify exit codes
3. **Prompt readthrough** — independent Evaluator-style readthrough of each modified agent prompt; verify no contradictory sections, no drift from existing tone
4. **Template validation** — placeholders in templates match what agent prompts reference
5. **Diff discipline** — each commit is atomic, single-FR scope, message-tagged `[harness:build] FR-N: ...`

## Constraints

- No changes outside `plugins/harness/`, `templates/`, `docs/`
- No breaking changes to manifest schema (new fields with safe defaults; existing v1.4 manifests must still load)
- All edits preserve existing section ordering — additive or in-place rewrites only
- Existing anti-leniency protocol, calibration examples, reward-hacking scan, RED FLAGS sections, prompt-injection defenses MUST remain functionally unchanged (additive in structure only)
- PR is for review — not auto-merge. Human gate before merge

## Rollout
