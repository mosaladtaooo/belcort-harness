# v2.3 — Agent-prompt deduplication + bash de-prescription (ADR)

**Status**: Accepted
**Date**: 2026-04-29
**Authors**: BELCORT (tao@belcort.com)
**Audit context**: Post-v2.2 audit pass. User-asked three questions during follow-up review: (1) "Generator execute develop — is it good enough?" (2) "Evaluator approach — is it still bloated?" (3) "Does bash and command line still need to be in prompts, or just natural language?" Fact-based read of `agents/generator.md` (526 LoC) and `agents/evaluator.md` (662 LoC) surfaced three single-source-of-truth violations and three over-prescriptive bash blocks.

## Decision

Apply v2.0/v2.2 minimalist refactor logic to three more accreted patterns. ~50-55 LoC net reduction across two agent files. Single atomic PR, no user-facing command surface change, no contract format change.

The three concrete changes — and where they sit on the Anthropic ruler — are:

| # | Change | Anthropic principle |
|---|---|---|
| A | Generator dedup: drop ANTI-PATTERNS section (subset of RED FLAGS table) + compress REWARD-HACKING — FORBIDDEN section (4 of 5 rules already in RED FLAGS) | *"Find the simplest solution possible, and only increase complexity when needed."* — single source of truth |
| B | Evaluator de-bash: Steps 1, 3, 4 converted from literal bash to natural-language intent. Step 4.5 reward-hacking scan kept literal (patterns ARE the spec). | *"Trust the model's ability to use its tools."* — agent-prompt staled assumption |
| C | Evaluator duplicate-warning fix: agent-level "READ THIS CAREFULLY" leniency warning deleted; mode-level copy at line 261 preserved | *"Stripping away pieces that are no longer load-bearing."* — single source of truth |

## Context — what staled, and why now

### The user's three questions

Tao asked three questions during the follow-up audit pass after v2.2 shipped: was Generator's BUILD approach sound, was Evaluator still fat, and was the literal bash in agent prompts still load-bearing.

### The three staled patterns

**Generator three-section TDD/reward-hacking restatement (Change A).** The `RED FLAGS` table (`generator.md:144-167`) is Anthropic's adversarial 1%-rule format — explicit rationalizations + counters in table form. Load-bearing. But the same content also appears as bullet lists in `## ANTI-PATTERNS` (`generator.md:498-505`) and as `NEVER` rules in `## REWARD-HACKING — FORBIDDEN` (`generator.md:507-525`). All ANTI-PATTERNS bullets and 4 of 5 REWARD-HACKING NEVER rules are restatements. The accretion came from drawing on multiple sources (Superpowers TDD discipline, Anthropic adversarial framing, BELCORT-specific reward-hacking countermeasures) without cross-pollination across passes — each section was added to a different Anthropic-aligned concern but ended up restating overlapping rules.

**Evaluator agent-level vs mode-level READ THIS CAREFULLY duplication (Change C).** The leniency-bias warning fires twice in `evaluator.md` — once at agent-level (line 54), once at EVALUATE-mode level (line 261), with the same Anthropic quote and near-identical wording. The agent-level copy primes ALL three modes (REVIEW-PROPOSAL, EVALUATE, REVALIDATE), but only EVALUATE involves numeric grading where Anthropic's documented leniency bias operates. REVIEW-PROPOSAL has its own failure mode (rubber-stamping, addressed at line 151) and REVALIDATE is binary PASS/FAIL (covered at line 246). The agent-level copy is mis-targeted — it warns against a bias that two of three modes don't have.

**Evaluator over-prescriptive bash (Change B).** Four bash blocks in `evaluator.md`. One (Step 4.5 reward-hacking scan) is genuinely load-bearing — the regex patterns ARE the spec, capturing test-file naming conventions, commit-message keywords for test weakening, and `.skip`/`xit` markers that Claude wouldn't infer from natural language. The other three (Step 1 setup, Step 3 code quality, Step 4 test suite) prescribe literal commands for generic operations Claude already knows: read these files in order, scan for these forbidden patterns, run the project's test command. The literal-bash assumption staled on Opus 4.7 the same way the per-FR story file assumption staled in v2.2 — the model can do this without a runbook.

For comparison: `planner.md:76` already explicitly states *"You do NOT have Bash. Planning is a read-and-write activity, not a command-execution activity."* — Planner has 0 bash blocks. The framework already trusts the model in one place; v2.3 extends the same trust to Generator and Evaluator's generic operations while preserving literal bash where the command IS the spec.

## Trade-offs

### What we gain

- **~50-55 LoC reduction** across `generator.md` (-20) and `evaluator.md` (-31). Smaller agent prompts = lower per-dispatch token cost = more headroom in 1M context.
- **Single source of truth** for TDD/reward-hacking discipline (RED FLAGS table) and for leniency-bias warning (EVALUATE-mode copy).
- **Stack flexibility** — Steps 3 and 4 of evaluator now work for TS/JS/Python/Rust/Go without TypeScript-specific assumptions baked in.
- **Alignment with v2.2's "trust the model" stance** — same logic that drove dropping the hard Planner size gate, now applied to bash-in-prompt assumptions.

### What we give up

- **Verbatim copy-pasteability of bash commands.** Pre-v2.3 evaluator Step 1 setup was paste-able into a terminal as-is. Post-v2.3, Claude has to translate intent to commands. Mitigation: Claude is the user of these prompts, not a human; this translation is reliable. Subagent dispatch prompts are not runbooks for humans.
- **Symmetry of leniency warnings across all evaluator modes.** Pre-v2.3 every mode saw the warning. Post-v2.3 only EVALUATE does. Mitigation: REVIEW-PROPOSAL and REVALIDATE have their own anti-pattern callouts addressing their specific failure modes. The asymmetry is correct, not regression.

### What we explicitly didn't do

- **Touch `planner.md`.** Already correct on bash philosophy.
- **Touch the RED FLAGS table format.** Anthropic's adversarial 1%-rule pattern is load-bearing.
- **Touch the Step 4.5 reward-hacking scan.** Patterns ARE the spec.
- **Address the user's ESLint 9 / config-resolution diagnostic.** String not in repo (grep verified). Source not yet identified by user. Deferred.
