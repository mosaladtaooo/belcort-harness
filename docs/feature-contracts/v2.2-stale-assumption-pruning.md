# v2.2 — Stale-assumption pruning + operational hardening (ADR)

**Status**: Accepted
**Date**: 2026-04-28
**Authors**: BELCORT (tao@belcort.com)
**Audit context**: Post-v2.1.9 cycle. User-reported Generator BUILD truncation incident (`001-foundation-and-ingestion`: 178 tool uses, 347.5 k tokens, 36 min, no implementation-report.md) prompted a full-framework re-stress-test against Anthropic's *"every component encodes an assumption that may go stale"* ruler.

## Decision

Apply the v2.0 minimalist refactor logic to four post-v2.0 stale-assumption targets plus two operational hardening items, in a single PR. ~300 LoC net reduction. No user-facing command surface change beyond removing one redundant front door (`/harness:negotiate` standalone, 17 → 16 commands).

The six concrete changes — and where they sit on the Anthropic ruler — are:

| # | Change | Anthropic principle |
|---|---|---|
| 1 | 1M-context confirmation banner (doctor + sprint Step 0b + quick + README) | Operational reliability — if the active model isn't [1m], the conditions for context-budget truncation re-emerge |
| 2 | Drop per-FR story files (`features/NNN/stories/FR-NNN.md`) | *"Every component in a harness encodes an assumption… those assumptions are worth stress testing… can quickly go stale as models improve"* |
| 3 | Generator pause `State at pause` snapshot for resume | *"Use structured files to carry previous agent state and next steps across context boundaries"* |
| 4 | Planner internal mode collapse (6 → 3); user-facing commands unchanged | *"Find the simplest solution possible, and only increase complexity when needed"* |
| 5 | Drop `/harness:negotiate` standalone command | *"Stripping away pieces that are no longer load-bearing"* |
| 6 | Soft-only Planner feature-size gate (advisory) | *"With Opus 4.6 I dropped context resets from this harness entirely"* — same logic, applied to the historical hard-gate intent |

## Context — what staled, and why now

### The trigger incident

A real sprint (`001-foundation-and-ingestion`, multi-stratum: deps + schema + RLS + adapters + auth + UI) hit Claude Code's per-subagent runtime ceiling at 347.5 k tokens. The default Opus context window is 200 k; the [1m] variant gives 1 M. The session was on the default, not the [1m] — silently, because agent frontmatter `model: inherit` resolves to whatever the CLI was launched with, and there was no preflight to surface that.

The scaffold-checkpoint protocol (added in v2.1.5) saved the work — 4 commits landed before truncation, recovery was possible. But the structural question surfaced: *was the framework still trusting model capability where capability was actually present?*

### The four staled assumptions

**Per-FR story files (Change #2).** Inherited from BMAD V6's "Scrum Master" pattern, where per-story files contain "everything the Dev agent needs — full context, implementation details, and architectural guidance embedded directly in story files." The implicit assumption: per-cycle reasoning quality improves when context is scoped to one FR vs the full bundled contract.

This was load-bearing on Opus 4.5/4.6 with a 200 k context. On Opus 4.7[1m], a typical 10-FR contract is ~8 k tokens — 0.8% of the available context. Per-cycle scoping is trivial without a separate file (the Generator can grep-and-read the relevant FR section directly). The story file became pure duplication enforced by a brittle rule: planner.md asserted *"stories must NEVER drift from the aggregate contract"* with hash-check enforcement claimed in evaluator.md — but the hash-check was Planner-asserted and Evaluator-unimplemented, a v2.x inconsistency where the documented contract and the running behavior already disagreed.

**Planner mode duplication (Change #4).** The Planner agent grew six modes (PLAN, CLARIFY-QUESTIONS, CLARIFY-APPLY, AMEND, EDIT, CONSTITUTION-AMEND) over v1.5 → v2.1.x. Four of these (CLARIFY-APPLY, AMEND, EDIT, CONSTITUTION-AMEND) shared ~95% of their procedure: read context → parse user change-request → write surgical patches to a `*-patches.md` file → exit without applying. Only the patches-file naming and a few mode-specific constraints differed.

The mode-specific constraints lived in BOTH planner.md mode sections AND each command file's dispatch prompt — three-way duplication for "AMEND can't touch constitution.md", "EDIT is cascade-aware", etc. The Anthropic principle of single source of truth per fact wasn't being honored at the agent-prompt layer. Collapsing to one shared mode (EDIT, marker-driven) put the constraints in their natural home: each command file's dispatch prompt, where the orchestrator-side ceremony already lived.

**`/harness:negotiate` standalone (Change #5).** The procedure (Generator NEGOTIATE → Evaluator REVIEW-PROPOSAL → Generator FINALIZE-CONTRACT, ≤3 rounds) is canonical in `commands/sprint.md` § 2c. The standalone command's three documented use-cases (per `commands/negotiate.md:13-15`) were all reachable via existing tools: `/harness:resume` for recovery from interrupted negotiation, `/harness:rewind negotiating` for restart. The standalone front door was almost never user-invoked — accreted, not load-bearing.

**Hard-gating Planner feature size (Change #6, the negative space).** The historical instinct was to add stricter gates as Generator BUILD truncations recurred. The user's stance — *"trust the model as it's going to more advanced"* — names the underlying choice: increase Generator capability via the [1m] context flag rather than constrain it via Planner gates. Anthropic's own evolution (*"With Opus 4.6 I dropped context resets from this harness entirely"*) is the precedent. The Planner size signals stay as advisory ("hey, this is huge, are you sure?") at the human gate, but the human is the decider, not a hard-blocking gate.

## Trade-offs

### What we gain

- **~300 LoC reduction** across planner.md (-400 from mode collapse), templates/features/story.md.txt deletion, commands/negotiate.md deletion, story-related rows across SKILL.md / README.md / dispatch prompts.
- **Single source of truth** per spec-edit constraint — each command file's dispatch prompt now authoritatively states what its Planner dispatch may patch and how, rather than mirroring text in planner.md.
- **Operational floor** on context-budget truncation — confirmation banner at session start, advisory check in doctor, README Quick Start promotion of the [1m] launch flag. This is the structural fix the user's incident asked for.
- **Resume safety** — `State at pause` snapshot survives interleaving commands between pause and re-dispatch; the previous loose-pinning of `state.current_task` could mis-orient the resumed Generator if `/harness:audit` or another command moved manifest state during pause.

### What we give up

- **One v2.0-preserved component goes** (story files). The v2.0 design spec at `docs/superpowers/specs/2026-04-21-belcort-v2-minimalist-refactor-design.md` line 112 explicitly preserved per-FR stories. v2.2 reverses that decision. **This is the kind of model-generation-over-model-generation tightening Anthropic's ruler explicitly endorses** — what was load-bearing on Opus 4.6 / 200 k can be stale on Opus 4.7 / 1 M. v2.0's preservation of story files was correct for its target model; v2.2's removal is correct for ours. Both decisions follow the same principle.
- **No mechanical 1M-context detection.** Claude Code does not currently expose `--model` to plugin scripts. The advisory banner relies on user confirmation. If the user launches without [1m] and confirms `Y` anyway, the conditions for the original truncation re-emerge. Mitigated by: prominent banner placement, explicit tradeoff in README, sprint Step 0b being a real prompt (not just a doc note). Future Claude Code versions exposing model info would let this become a hard check; tracked in v3 watch list.

### What we explicitly didn't do

The v3 watch list (in ROADMAP.md) captures four items considered and deferred:

1. **Stratum-splitting BUILD into N dispatches.** Premature on confirmed-1M sessions. Revisit only if truncation recurs after Change #1 lands.
2. **Pause-mechanic full unification** (Planner AskUserQuestions vs Generator file-based). The asymmetry is correct on current models — Planner is interactive discovery, Generator is long-running autonomy. File-based pause IS the right tool for long-running work.
3. **Audit-family merge** (`/analyze`, `/validate`, `/audit`, `/retrospective`, `REVALIDATE`). Each answers a distinct question per `SKILL.md` § Audit Commands. Merging produces a meta-audit that's slower and harder to interpret.
4. **Story-file deprecation grace period.** Existing projects with `stories/` folders are simply ignored from v2.2 forward — no warning code, no migration script. The hash-check that would have failed on drift was never enforced, so no spurious failures occur.

## Operational dependency (load-bearing for the trust-the-model stance)

**Change #6 (soft-only Planner gate) depends on Change #1 (1M-context confirmation).** Without 1M context active, the conditions that drove the historical hard-gate intent return. The CHANGELOG entry, the planner.md rationale paragraph, and the sprint Step 0b prompt all state this explicitly. They ship together or neither ships.

If a future audit revisits this stance — e.g., a model regression that re-introduces context anxiety even on a 1M variant — Change #6 is the first reversal target. Change #1 stays regardless.

## Implementation method

- **Design spec**: `docs/superpowers/specs/2026-04-28-belcort-audit-and-refine-design.md` (430 lines, full per-change before/after with file paths and test plans)
- **Implementation plan**: `docs/superpowers/plans/2026-04-28-belcort-audit-and-refine.md` (1,477 lines, 31 atomic tasks grouped into 7 spec-change groups)
- **Execution mode**: Subagent-Driven Development (`superpowers:subagent-driven-development`) — fresh implementer subagent per Spec Change group, two-stage review (spec compliance + code quality) per group, inline fixes for mechanical text-replacement misses caught in review

Per-group review surfaced multiple real issues each fixed before moving on, including:
- Group A: heading-numbering collision with existing brainstorm `## 0a` (sprint.md needed 0a/0b/0c renumbering)
- Group B: residual `stories/` references in pause-questions template + sprint.md line 196 that the implementer's literal task list missed
- Group D: 5 stale step-headings ("AMEND mode", "CLARIFY-APPLY mode", etc.) in command files where the dispatch BODY was correctly rewritten but the surrounding documentation lagged
- Group E: 5 secondary `/harness:negotiate` references in agent frontmatter and amend.md user messages that the spec didn't enumerate but which broke after the file deletion

This is the v2.0 minimalist-refactor pattern of "single design + single plan + atomic merge" applied to the v2.1.x patch-accretion. The CHANGELOG documents the contradiction with v2.0's preservation of story files explicitly under "Removed" with rationale.
