# Feature Contract — v1.4 SpecKit / BMAD alignment pass

**Branch**: `harness/v1.4-speckit-bmad-alignment`
**Base**: `harness/v1.3-v1.4-combined`
**Date**: 2026-04-20
**Status**: In review (PR open for human gate)

## Why this exists

Audit against Anthropic's [harness-design-long-running-apps](https://www.anthropic.com/engineering/harness-design-long-running-apps) + [trustworthy-agents](https://www.anthropic.com/research/trustworthy-agents) posts, plus SpecKit (`github/spec-kit`), BMAD (`bmad-code-org/BMAD-METHOD`), and Superpowers (`obra/superpowers`) surfaced five gaps worth closing before v1.4 lock. Each one is a load-bearing pattern the harness borrowed-but-didn't-fully-absorb. This PR brings them to parity.

## Scope — FRs

| FR | Title | Source tradition | Rationale |
|----|-------|------------------|-----------|
| FR-1 | `/harness:analyze` emits FR-by-FR coverage table | SpecKit `/analyze` | Current summary counts say *whether* drift exists; table says *where*. Turns invisible gaps into checkable claims. |
| FR-2 | Doctor verifies `jq`-or-`python3` presence | Anthropic trustworthy-agents §defenses-at-every-level | Pre-tool-use.sh currently fails open without either, disabling force-push, `.harness/` deletion, and test-file deletion guards. Doctor must catch this. |
| FR-3 | Adversarial red-flags sections in Planner + Generator prompts | Superpowers "1% rule with red flags" | Evaluator has anti-leniency bias warnings; Planner + Generator don't. Adversarial prompting against each agent's known cheat paths. |
| FR-4 | Two-stage Evaluator report — Contract Compliance (binary) before Quality Scoring (numeric) | Superpowers two-stage review | Current single-pass grading mixes correctness and craft; good code gets rejected for style, missing features get masked by high craft scores. |
| FR-5 | Ship artifact templates for contract / proposal / review / implementation-report / eval-report | BMAD story-file templates + SpecKit task templates | Agents currently author structure from scratch each run. Templates reduce shape drift and speed subagent work. |

## ACs (testable)

### AC-1.1 — Coverage table format
`/harness:analyze` output contains a markdown table with one row per FR mapped to: (a) architecture trace, (b) contract deliverable, (c) test-criterion mapping. Empty cells rendered as `NO` (not blank), making gaps visually loud.

### AC-1.2 — Coverage table preserves summary
The existing summary block (FR count, CRITICAL/WARNING lists) remains — the table is additive, not replacing.

### AC-2.1 — Doctor checks parser
`scripts/doctor.sh` adds a CRITICAL check named "JSON parser (jq or python3)" that FAILs if neither is present. Fix text: `brew install jq  |  or: apt install jq` (platform-neutral hint).

### AC-2.2 — Pre-tool-use self-test
No change to `pre-tool-use.sh` (it already fails open gracefully). The doctor check is the preventive layer.

### AC-3.1 — Planner red-flags section
`agents/planner.md` gains a "Red Flags — you're about to skip this" section near the top, enumerating ≥4 specific rationalizations (e.g., "I know React, skipping Context7 lookup", "This NFR is obvious, not writing it down").

### AC-3.2 — Generator red-flags section
`agents/generator.md` gains the same, enumerating ≥4 Generator-specific cheats (e.g., "Test can wait", "Stubbing this is fine for now", "Skipping refactor, it works").

### AC-3.3 — Adversarial framing preserved
Both sections use the Superpowers phrasing pattern: "You're about to rationalize skipping this — label each rationalization as a RED FLAG, stop, do the work."

### AC-4.1 — Two-stage report structure
`eval-report.md` template in `agents/evaluator.md` is reorganized so **Part A — Contract Compliance** (binary per FR/AC, computed first) precedes **Part B — Quality Scoring** (numeric, computed second). Part A produces a table: `FR/AC | Requirement | Met? (Y/N) | Evidence`.

### AC-4.2 — Gating rule
If Part A shows any FR at `Met? = N`, the feature FAILs regardless of Part B scores. This is explicit in the prompt ("compliance gates quality").

### AC-4.3 — Existing criteria preserved
The four criteria (Functionality / Code Quality / Test Coverage / Product Depth) remain. They live in Part B. The anti-leniency protocol and calibration-benchmark table are unchanged.

### AC-5.1 — Templates exist
`templates/features/` contains: `contract.md.txt`, `proposal.md.txt`, `review.md.txt`, `implementation-report.md.txt`, `eval-report.md.txt`. Each file is ≤200 lines, uses `{{placeholder}}` notation for fill-ins, matches the structure currently embedded in agent prompts.

### AC-5.2 — Agents reference templates
Planner, Generator, Evaluator prompts reference the template paths (e.g., "Use the structure in `templates/features/contract.md.txt`"). No duplication of full template content in agent prompts.

### AC-5.3 — Templates self-document
Each template's first line is `<!-- BELCORT Harness — Template: <name> -->`, followed by a short comment describing what fills it and when.

## Testing strategy

This is a prompt-engineering + shell-script repo — no Playwright, no test runner. Verification is:

1. **Lint pass** — `bash -n` on modified shell scripts (doctor.sh, pre-tool-use.sh).
2. **Doctor dry-run** — run `doctor.sh` on macOS, verify new check appears in output and exits correctly on both `jq present / both missing` simulated states.
3. **Prompt readthrough** — independent Evaluator subagent (fresh context) reads each modified prompt end-to-end, verifies it still coheres, no contradictory sections, no drift from existing tone.
4. **Template validation** — Evaluator subagent verifies template placeholders match what agent prompts actually reference.
5. **Diff discipline** — each commit is atomic, single-concern, message-tagged `[harness:build]` per existing convention.

## Constraints

- No changes outside `plugins/harness/` and `templates/` and `docs/`.
- No breaking changes to manifest schema or `.harness/` layout.
- All edits preserve existing section ordering — only additive or in-place rewrites.
- Existing anti-leniency protocol, calibration examples, reward-hacking scan MUST remain functionally unchanged (additive in structure only).
- PR is for review — not merge. Human gate before merge.
