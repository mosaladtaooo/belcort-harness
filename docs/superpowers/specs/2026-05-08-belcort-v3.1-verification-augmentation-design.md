**Date**: 2026-05-08
**Author**: BELCORT (tao@belcort.com)
**Target model**: `claude-opus-4-7[1m]` (1M context variant — load-bearing for v3.1+ per v3.0 § 8.2)
**Refactor scope**: Single atomic v3.1.0 PR. Eight verification-augmentation additions covering 4 dimensions: operational reliability (A2), test-suite quality (B1+B2), accessibility + bundle-size guardrails (B4+B6 partial), planning rigor (C4), code-quality second-opinion (D3), and refactor-pattern documentation (D2 stub). Predicted net LoC: +310-360 (~1/3 the scale of v3.0's +850).
**Predecessors**:
- `docs/superpowers/specs/2026-05-07-belcort-v3-runtime-verification-and-audit-design.md` (v3.0 — runtime-verification phase + audit pass, ~+850 LoC)

## 1. Context & Motivation

v3.0 shipped a substantially better harness — 8 production-bug-classes closed via SIMULATE + contract-template tightening + Evaluator Step 2 lightening. But v3.0's own README "What's new" section, CHANGELOG operational notes, and ROADMAP v3 watch list documented honest gaps the harness still doesn't address:

| Gap surfaced post-v3.0 | What v3.0 ships | What's still missing |
|---|---|---|
| Worker readiness | 30s polling + 3x retry in SIMULATE Step 3 | Positive readiness signal (no false NEEDS-REPAIR on slow-warming workers) |
| Test-suite quality vs implementation quality | Reward-hacking syntactic scan (test-deletion + .skip + trivial-assertion) | Semantic test weakness — tests that pass against broken code |
| Accessibility | Prose-only mention in `criteria.md.txt:138` | First-class enforcement |
| Bundle-size regressions | None | Deterministic budget gate |
| Familiarity bias in framework selection | RED FLAG row 5 in Planner (prose nudge) | Forced multi-alternative comparison with verifiable existence |
| Code-quality second opinion | Single Evaluator's adversarial review | Independent code-reviewer perspective formalized into the flow |

After v3.0 shipped, three parallel research subagents (under directive `mcp__claude_ai_Context7__*` for ecosystem docs since the bundled MCP was disconnected) surveyed eight specific iteration vectors across operational gaps (Category A), verification depth (Category B), and planning + code quality (Categories C + D). Findings synthesized into ratified scope: ship the highest-ROI six core items + one partial item + one prose stub as v3.1.0.

### Anti-goal

Not a redesign. Not a paradigm shift. v3.0's three-agent topology (Planner / Generator / Evaluator) + file-based handoffs + fresh subagent contexts + atomic-PR release discipline are preserved verbatim. v3.1 is augmentation: each addition is bounded, low-coupling, and reversible. Every item has an explicit "When to revisit" condition for any deferral.

## 2. The Ruler

Same 5 Anthropic principles as v3.0, plus 4 user-stated constraints carried forward:

1. *"Find the simplest solution possible, and only increase complexity when needed."* — Rajasekaran 2026
2. *"Every component encodes an assumption … assumptions are worth stress testing … can quickly go stale as models improve."* — Rajasekaran 2026
3. *"Communication was handled via files."* — Rajasekaran 2026
4. *"Separating the agent doing the work from the agent judging it proves to be a strong lever."* — Rajasekaran 2026 (GAN isolation, non-negotiable)
5. *"With Opus 4.6 I dropped context resets from this harness entirely."* — Rajasekaran 2026 (continuous-session principle)
6. **Verification > audit weight.** v3.1 is verification augmentation, not a v3.0-style audit pass. Audit polish was v3.0's Phase 2; v3.1 is purely additive.
7. **Atomic v3.1.0.** Single PR, single minor version bump. No staged rollout.
8. **Three-agent topology preserved.** No 4th subagent type. Anti-rec 10.1 from v3.0 source report still binding.
9. **Anti-leniency preservation is non-negotiable.** v3.1 introduces a code-reviewer integration (D3) whose collaborative-skeptic framing could erode Evaluator's adversarial framing if integrated naively. Output-translation rules are mandatory.

## 3. Goals & Non-goals

### Tier 1 goals (G1–G3, lowest-risk-highest-value triple)

- **G1 (A2).** Add **worker readiness signal via stdout pattern matching** to SIMULATE Step 2.5. Replace 30s polling with positive Bash `run_in_background` + `until grep -q "<pattern>"` pattern. Convention-only fallback for projects that don't declare; per-architecture declaration becomes new-sprint default. Eliminates false NEEDS-REPAIR on slow-warming workers; eliminates false-positive successes on warm-but-stale workers (cross-FR resource leaks).
- **G2 (B4).** Add **`@axe-core/playwright` accessibility testing** to SIMULATE Step 3 per State-Transition row. Promote `criteria.md.txt:138`'s prose mention to first-class enforcement. PRD Pass 1 declares WCAG conformance level (default AA) via `AskUserQuestions`. Catches missing aria-labels, color-contrast violations, keyboard traps — bug class LLMs reliably ship.
- **G3 (D3).** Integrate **`superpowers:code-reviewer`** as Evaluator EVALUATE Step 3a (mechanical scan via dispatched Task subagent), with **anti-leniency-preserving output translation** (drop "Strengths" section verbatim, drop "Assessment" section, map Critical/Important/Minor to BELCORT's Critical/Major/minor). Soft-fallback if `superpowers` plugin not installed (existing v3.0 Step 3 behavior). Formalizes a pattern already used manually (per v3.0 review session).

### Tier 2 goals (G4–G6, stronger machinery)

- **G4 (B1).** Add **Stryker.js mutation testing** to Evaluator Step 4. `@stryker-mutator/core` + `@stryker-mutator/vitest-runner` with `incremental: true` mandatory + `--mutate src/<feature-path>/` per-FR scoping. NEGOTIATE proposes per-FR mutation-score target (default 70% on critical paths, 50% standard). Catches the semantic-test-weakness bug class Anthropic's reward-hacking research specifically identifies for LLM-generated tests.
- **G5 (B2).** Add **fast-check property-based testing** as Generator BUILD per-FR option. `@fast-check/vitest`. NEGOTIATE proposes property-test eligibility per FR (Y for pure functions / parsers / aggregators / concurrent ops; N for UI flows). Pairs with G4 (mutation testing requires property-augmented suite to mature). Race-condition detection via `fc.scheduler()` covers a class SIMULATE's sequential driving cannot reach.
- **G6 (C4).** Add **MADR-style ADR matrix** to Planner Pass 2 architecture emission. Replace existing loose "Considered: A, B, C with brief tradeoffs" with structured: ≥3 Decision Drivers (≥2 NFR-NNN refs) + ≥2 Considered Options (Context7-verified to exist) + per-driver scoring matrix + 1-sentence rationale tied to highest-scoring driver. New self-validation row V8b. Closes familiarity-bias bug class with verifiable structure (Context7 lookup of alternatives is the genuinely novel anti-hallucination contribution).

### Tier 3 goals (G7–G8, opportunistic / documentation)

- **G7 (B6 partial).** Add **`size-limit` bundle-size budget** to Evaluator Step 4. PRD declares per-chunk + total budget; Evaluator asserts `size-limit run` against budget. Skips full Lighthouse CI Web Vitals (deferred — lab-vs-field variance erodes anti-leniency). Bundle-size is deterministic, low-flake.
- **G8 (D2 stub).** **Generator BUILD RED FLAG row 7 update** + **SKILL.md `## Refactor Pattern (v3.1)` section**. Document how to express refactor-shaped work via `/harness:quick` with a refactor-shaped contract template. NO new `/harness:refactor` command. Defers full command to v3.2 pending real usage data.

### Non-goals (deferred to v3.2+)

- **N1 (A1).** Real-time worker log tailing via Monitor tool. **Deferred — empirical Monitor-in-subagent confirmation needed.** Public Anthropic docs don't confirm Monitor is callable from plugin-declared subagents. Sandbox test in v3.2 before integration. v3.0's post-hoc tail-100 covers ~80% of value.
- **N2 (A5).** Parallel cumulative regression via fork-subagent. **Deferred — ROADMAP item 1 revisit condition not met.** No real project at N≥10 shipped features with painful serial regression. Adding 180-250 LoC of fanout-merge complexity = YAGNI.
- **N3 (B3).** Visual regression. **Deferred — false-positive risk too high.** 4 documented Playwright font-rendering issues; OS-specific baselines; no LLM-specific signal. Erodes anti-leniency through noise.
- **N4 (B5).** Cross-browser projects matrix. **Deferred — opt-in only.** No LLM-specific bug class. 3x cumulative regression cost. Most BELCORT users today ship internal tools, not public-facing sites.
- **N5 (B6 full).** Lighthouse CI Web Vitals. **Deferred — lab-vs-field variance.** Bundle-size piece (G7) is the deterministic v3.1 portion. Full Lighthouse waits for evidence Web Vitals signal exceeds CI noise.
- **N6 (D2 full).** `/harness:refactor` command. **Deferred to v3.2 with usage-data gate.** v3.1 stub (G8) closes documentation gap; full command waits for real refactor-via-/quick usage data showing the pattern is insufficient.
- **N7.** Evaluator Context7-awareness for framework method verification. **Deferred — separable scope.** Could add Step 3 sub-step "verify Generator's framework usage matches current API patterns via Context7." Worth investigating in v3.2 when D3 telemetry shows what code-reviewer catches vs misses.

Each change follows the v3.0 spec template: **Problem → Evidence → Change → Files affected → Risk → Test → Ruler fit**. Ordered by dependency and Tier.

### Change 1 — A2 (G1): Worker readiness signal via stdout pattern matching

**Problem.** SIMULATE Step 2 sub-step 5 (`agents/generator.md` ~line 690) polls server bind via Playwright `playwright_navigate` retry with 30s timeout — works for HTTP servers but is silent on workers without HTTP ports. v3.0 perfect-pass added 3x retry with 10s backoff in Step 3, but it's still polling.

**Evidence.** Source-report-style observation: a worker that takes 35s to bind (slow CI, slow DB pool) is treated as infrastructure failure → false NEEDS-REPAIR. A worker that's warm-but-stale (PID leak from prior SIMULATE) handles state transitions using cached pre-migration data → false-positive success.

**Change.** Two parts:

**(a)** `agents/generator.md` SIMULATE Step 2 gains a new sub-step 2.6 (after server bind, before Step 3):

```markdown
**Worker readiness signal (v3.1+).** If the worker exists AND
architecture.md or proposal.md declares `worker_ready_pattern`, use Bash
`run_in_background: true` with:

    until grep -q "<pattern>" logs/worker.log; do sleep 0.5; done

Wrap with `timeout 30 bash -c '...'` for safety. On match, proceed to
Step 3 — REMOVE the worker-readiness-retry policy from Step 3 (the worker
is already warm; retrying masks real bugs per the existing rule for
non-worker rows). On timeout, treat as infrastructure failure: kill
captured PIDs, write `## Infrastructure failure` to simulation-report.md
with verdict NEEDS-REPAIR, exit.

If no `worker_ready_pattern` declared, use the convention-only fallback:
look for one of the canonical patterns from SKILL.md § Worker Readiness
Patterns: `Server listening on`, `worker ready`, `[ready]`,
`READY:GO`, `Database connection established`, `Queue subscribed`. If
none of these match within 30s, fall back to v3.0's polling behavior.
```

**(b)** `agents/planner.md` Pass 2 architecture emission step gains a worker-readiness declaration:

```markdown
**Worker readiness signal (v3.1+).** When the architecture includes a
worker process, declare in the worker subsection:
`worker_ready_pattern: "<exact-anchored-regex>"` — e.g.,
`worker_ready_pattern: "^WORKER:READY$"`. Anchor the pattern to avoid
false-ready from debug logs. If no stable readiness signal exists (worker
idles silently), omit the declaration; SIMULATE falls back to canonical-pattern
detection.
```

**(c)** `skills/harness/SKILL.md` gains a new subsection `## Worker Readiness Patterns (v3.1)` listing the canonical 6 patterns (per the convention-only fallback list above).

**Files affected:** `agents/generator.md` (+~30 lines), `agents/planner.md` (+~15 lines), `skills/harness/SKILL.md` (+~25 lines).

**Risk.** Low. Backward-compatible: existing v2.x/v3.0 sprints without `worker_ready_pattern` use convention-only fallback; pattern unmatched → original 30s polling. New sprints that DO declare benefit immediately.

**Test.** Self-test 1 in § 10.2.

**Ruler fit.**
- **#1 simplest** — Bash `run_in_background` + `until grep -q` is the canonical Anthropic-doc pattern. No new tools.
- **#2 stable** — assumption "worker stdout/log emits readiness pattern" stable across Node/Python/Go/Rust workers; convention-only fallback handles silent-idle workers.
- **#5 continuous-session** — produces exactly one completion notification regardless of session length. Zero turn-burn.

### Change 2 — B4 (G2): axe-core accessibility in SIMULATE Step 3

**Problem.** v3.0 SIMULATE Step 3 drives State-Transition rows via Playwright but has no a11y assertions. `templates/evaluator/criteria.md.txt:138` mentions axe-core as opt-in NFR suggestion (prose only, not enforced). LLMs reliably ship missing aria-labels, contrast violations, heading-skip patterns.

**Evidence.** Web research: axe-core catches ~30-40% of WCAG issues; rule-based; low false-positive rate. Already mentioned in BELCORT's evaluator criteria template as a recommendation but never formally invoked. SIMULATE's already-running Playwright session in Step 3 is the natural insertion point (zero new infrastructure).

**Change.** Three parts:

**(a)** `agents/planner.md` Pass 1 gains a WCAG-conformance question:

```markdown
**Sub-step W: Accessibility conformance (v3.1+)**

When the project has any UI surface, ask the user via AskUserQuestions:

> "What WCAG conformance level should this project meet?
>   1. AA (recommended default — public-facing apps)
>   2. AAA (strict — government / accessibility-critical)
>   3. A only (internal tools — minimal)
>   4. N/A (no UI — non-applicable)"

Record the answer in prd.md under `## Accessibility NFR` as `WCAG-Level: A | AA | AAA | N/A`.
```

**(b)** `agents/generator.md` SIMULATE Step 3 gains an axe-core assertion per row:

```markdown
**Accessibility scan per row (v3.1+).** After driving each State-Transition
row's user flow but before recording the verdict, run:

    const axeResults = await new AxeBuilder({ page })
      .withTags(['wcag2a', 'wcag2aa'])
      .analyze();

(Adjust tags per PRD-declared WCAG level: A → wcag2a only, AAA → +wcag2aaa.)

If `axeResults.violations.length > 0`:
- For each violation with `impact` ≥ `serious`: row's a11y column = ❌
  (treats parent FR as Partial — same as DB ❌ rule)
- For each violation with `impact` = `moderate` or `minor`: row's a11y
  column = ⚠️ (records under Major findings; doesn't fail Part A)

Record a new `a11y` column in simulation-report.md per-state-transition
table. If WCAG-Level is N/A, skip this scan entirely and emit
`a11y: N/A — non-UI feature`.
```

**(c)** `templates/evaluator/criteria.md.txt:138` prose mention is upgraded to first-class:

```markdown
**Accessibility (NFR-driven, v3.1+):**
- If PRD declares `WCAG-Level: A | AA | AAA`, axe-core violations from
  simulation-report.md a11y column with `impact ≥ serious` count toward
  Part A FAIL.
- `impact ≥ moderate` violations are MAJOR findings.
- Per-rule disable allowed via `axe.run({rules: { 'rule-id': {enabled: false}}})`
  with mandatory ADR justifying disable.
```

**(d)** `templates/features/simulation-report.md.txt` gains a11y column in per-state-transition table.

**Files affected:** `agents/planner.md` (+~15 lines), `agents/generator.md` (+~25 lines), `templates/evaluator/criteria.md.txt` (+~10 lines), `templates/features/simulation-report.md.txt` (+~5 lines), Generator NEGOTIATE proposal template (+~5 lines for a11y section ack).

**Risk.** Low-to-medium. Project must `npm i -D @axe-core/playwright axe-core` (~5MB). Some axe rules produce subjective findings (best-practices); per-rule disable + WCAG-tag scoping mitigates.

**Test.** Self-test 2 in § 10.2.

**Ruler fit.**
- **#1 simplest** — one library, one method call per Playwright session, leverages SIMULATE's already-running browser.
- **#2 stable** — assumption "WCAG conformance matters for UI projects" stable; project-shape escape (N/A for non-UI) handles edge cases.

### Change 4 — B1 (G4): Stryker.js mutation testing in Evaluator Step 4

**Problem.** v3.0's reward-hacking scan (Evaluator Step 4.5) catches *syntactic* test weakness (`.skip`, `toBeTruthy` patterns, deleted test files) but not *semantic* weakness — tests that pass against broken code because assertions are too weak (`expect(arr.length).toBeGreaterThan(0)` when the contract requires `=== 3`). Anthropic's reward-hacking research specifically identifies this as the LLM-test bug class BELCORT's anti-leniency protocol fights against.

**Evidence.** Web research: testdouble.com 2026 article frames mutation testing as the antidote to LLM-written tests' blind spots. Sparkbox + codemanship 2026 articles describe LLM-generated tests as "leaving gaping holes." Stryker is the only mature TS-supporting option (LLMorpheus is research-grade; Mutmut is Python-only).

**Change.** Three parts:

**(a)** `agents/generator.md` BUILD scaffolding gains a mutation-config-write rule:

```markdown
**Mutation testing config (v3.1+).** When scaffolding a new project (Phase 1
of BUILD), write `stryker.config.json` with:

```json
{
  "$schema": "https://raw.githubusercontent.com/stryker-mutator/stryker-js/master/packages/core/schema/stryker-schema.json",
  "testRunner": "vitest",
  "incremental": true,
  "thresholds": {
    "high": 80,
    "low": 60,
    "break": null
  },
  "mutate": ["src/**/*.ts", "!src/**/*.spec.ts"]
}
```

Include `@stryker-mutator/core` + `@stryker-mutator/vitest-runner` in
package.json devDependencies. (Cost gate: if project has fewer than 100
LoC of source, skip — mutation overhead exceeds value.)
```

**(b)** `agents/generator.md` NEGOTIATE proposal template gains mutation-score-target column:

```markdown
**Mutation score target (v3.1+).** For each FR, declare a mutation-score
target: 70% on critical paths (auth, payment, data-mutation), 50% on
standard FRs, N/A on non-testable FRs (config-only, type-only). Generator
NEGOTIATE commits to scoring; BUILD writes tests aiming for the target.
```

**(c)** `agents/evaluator.md` Step 4 gains mutation gate:

```markdown
**Mutation gate (v3.1+).** After running `npx vitest run`, run:

    npx stryker run --incremental --mutate "src/<feature-folder-paths>/"

Wait for completion. Parse `reports/mutation/mutation.json`:
- If `mutationScore` < contract's per-FR target by ≥10 points → MAJOR finding
- If `mutationScore` < 30% on any per-FR module → CRITICAL finding
- Equivalent mutants (annotated by Stryker as `EquivalentMutant`) are NOT
  counted against Generator — their `excludedMutations` config addition
  must be ADR-justified

If Stryker errors out (cannot run incremental DB, missing config), this is
infrastructure failure NOT test failure — file `## Mutation Infrastructure
Failure` finding and proceed; do not block Part A on Stryker unavailability.
```

**Files affected:** `agents/generator.md` (+~40 lines for scaffolding + NEGOTIATE columns), `agents/evaluator.md` (+~30 lines for Step 4 mutation gate), `templates/features/contract.md.txt` (+~10 lines for Mutation Score Target table).

**Risk.** Medium. Cost: 30-90s incremental on 1k-LoC features after first run; 5-15min cold start. Mitigation: `--incremental` mandatory + per-FR scoping + cost gate (skip if < 100 LoC source).

**Test.** Self-test 4 in § 10.2.

**Ruler fit.**
